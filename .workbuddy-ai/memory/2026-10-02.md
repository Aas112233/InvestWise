## Session audit (user asked: mid-session user change / tenant shift?)

Read-only audit of auth chain: lib/middleware/auth.ts, app/api/auth/refresh +
logout, server/src/lib/session.ts, lib/api-client.ts, middleware.ts,
app-shell.tsx, auth-context.tsx. NO code changed yet — fixes pending user OK.

Findings (ranked):
1. **2-minute inactivity force-logout** — app-shell.tsx `useInactivityTimeout
   ({timeoutMs: 2*60*1000, warning 60s})` → logout() → /login?session=timeout.
   Dominant cause of "session dies mid-work".
2. **Idle tab revokes shared session** — cookies are shared across tabs;
   /api/auth/logout blacklists the REFRESH token, so one idle tab's auto-logout
   kills every other tab's ability to refresh.
3. **apiClient has NO 401 interceptor / auto-refresh** — nothing calls
   /api/auth/refresh during normal API use (only AppShell's extend button).
   15m access expiry surfaces as raw request failures; edge middleware still
   lets pages load → half-broken states.
4. **Multi-tab refresh rotation race** — concurrent refresh → unique-violation
   23505 → TOKEN_REVOKED 401 → handleExtend catch → full logout despite valid
   session elsewhere.
5. **Security: server/src/lib/session.ts skips the blacklist check entirely**
   (only JWT verify + user lookup, 60s userId-keyed cache) — a revoked access
   token still authenticates server-module routes (funds transfer, finance
   handlers) up to its 15m expiry. Fix: blacklist check on cache miss (or
   route through getAuthContext).
6. NOT bugs: tenantId/role/permissions re-read from DB per request — admin
   changes propagate ≤30s (app routes, 30s token-keyed authCache) / ≤60s
   (server routes); no cross-tenant session bleed; impersonation is by design.

Proposed fixes (awaiting user decision): raise idle timeout to 30m; apiClient
single-flight auto-refresh interceptor on 401 (retry once, real logout only on
TOKEN_REVOKED); blacklist check in session.ts; idle-tab logout without server
revoke (or rely on long timeout).

## Public API hardening implemented (same day, later)

Fixes for all audit findings:

- **lib/request-meta.ts**: added `readCappedJson(request, maxBytes)` (cap on
  bytes actually read, throws ValidationError; signup route refactored onto it)
  and `clampText(value, max)` (free-text clamp; non-string/blank → null).
- **lib/cron-auth.ts** (new): `authorizeCronRequest` — timing-safe
  `timingSafeEqual` bearer check, fails closed; distinguishes
  CRON_NOT_CONFIGURED from UNAUTHORIZED. Both cron routes now use it.
- **login route**: IP budget `login:ip` 30/15min (60 when IP unknown), spent in
  parallel with the capped 4KB body read (no sequential latency add); dummy-
  bcrypt compare (`equalizePasswordTiming`, lazily derived hash) on unknown
  email kills the timing enumeration oracle; location country/city/region
  clamped via clampText (was unvalidated → varchar overflow 500s); non-object
  JSON body (e.g. `null`) guarded → 400 instead of TypeError → 500.
- **forgot-password route** (rewritten): `forgot:ip` 5/15min (20 unknown) +
  `forgot:email` 3/hour budgets, 4KB body cap, ONE audit row per request
  regardless of account existence (uniform work kills the timing oracle; the
  audit row IS the feature — no email provider exists), honest response copy,
  ValidationError → 400 branch. Status 'PENDING' so admins can act on rows.
