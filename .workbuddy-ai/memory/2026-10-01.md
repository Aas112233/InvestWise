# 2026-10-01 — Performance pass: round-trip waste + missing indexes

User reported the app feels slow. Audit (Explore agent) + fixes applied. DB latency
re-confirmed: `SELECT 1` = **239–257ms** per round trip (1.7s cold TLS) against the
Tokyo pooler — region remains the #1 floor; everything below reduces round trips.

## N+1 fixes (server/src/modules/meetings/service.ts)
- Replaced `resolveDepositStatusForMember` (per-member SELECT) with
  `resolveDepositStatusForMembers` — one grouped `MIN(date)` query for a whole
  roster. Used by `createMeeting` (was N SELECTs inside the tx) and
  `completeMeeting` (was ~2N statements; now 1 read + ≤3 grouped updates via
  `inArray` status buckets).
- `recordAttendance` → single multi-row upsert on `uq_meeting_member`
  (`onConflictDoUpdate` with `excluded.*`); duplicate memberIds collapsed
  keeping LAST (matches old sequential overwrite).
- `app/api/meetings/[id]/attendance/route.ts` — same upsert + ONE grouped
  `warningCount + 1` UPDATE for all ABSENT members.

## Batched writes
- `server/src/modules/arrears/service.ts` `calculateMonthlyArrears`: per-member
  UPDATE/INSERT loop (no tx!) → in-memory compute + tx { grouped UPDATE …FROM
  (VALUES …) + multi-row INSERT + audit }. Reads depositAgg/existingArrears
  now parallel.
- `app/api/dividends/distribute/route.ts`: per-member loop (3 writes × N) →
  multi-row transaction inserts + ONE grouped `members` equity update
  (`UPDATE … FROM (VALUES …) WHERE m.tenant_id = scopedTenantId`) + multi-row
  profitAllocation inserts. 5 pre-reads (dup-ref, settings, distributable
  fund, reserve fund, active members, fiscal-period lookup) → one Promise.all;
  fiscal period CREATE still happens only after validation (explicit
  fiscalPeriodId that doesn't resolve stays null, as before).
- `app/api/dividends/calculate/route.ts`: 4 pre-reads → Promise.all.

## Parallelized sequential queries (Promise.all, error precedence preserved)
- `app/api/deposits/route.ts` POST + `deposits/request` + `[id]/approve` +
  `[id]/reject` — dup-ref/member/fund lookups batched (optional member/
  project use `sql\`false\`` when id absent).
- `app/api/auth/login` — 5 independent writes (loginAttempts, lastLogin,
  subscription gate, session, audit) → one Promise.all; token signing waits

- `app/api/auth/refresh` — blacklist+user batched; rotation insert + sub

- `app/api/expenses` POST — dup-ref/fund/project batched.
- `server/src/modules/finance/share-consistency.ts` — per-project SUM loop →
  one GROUP BY (file still excluded from tsconfig).
- `app/api/settings` GET — `checkAndAutoLockShareValue` now RETURNS the fresh
  settings row (no second read of the same row). Deliberately NOT touched:
  `/api/auth/me` fresh re-SELECT (profile freshness beats 1 RT).

## Indexes (added to BOTH schema mirrors + applied live, idempotent)
- `transactions (tenant_id, reference_number) WHERE is_deleted = false`
  → `idx_trans_tenant_reference` (48 kB) — dup-checks in 4 routes.
- `member_arrears (period_key)` → `idx_arrears_period` (8 kB).
- `blacklisted_tokens.token` — live DB ALREADY had a unique token index
  (schema files were just missing the declaration; now synced as
  `uniqueIndex('uq_blacklisted_tokens_token')`).
- Applied via `.workbuddy-ai/tmp/add-indexes.mjs` (CREATE INDEX IF NOT EXISTS,
  safe to re-run; uses DATABASE_URL from .env.local).
